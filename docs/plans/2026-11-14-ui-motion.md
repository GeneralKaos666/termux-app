# Shell UI motion — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Compose shell's motion fluid and springy, and add the missing tab and float transitions.

**Architecture:** Declarative Compose animation only — spring specs on the two chrome transitions, `animateItem`/`animateColorAsState`/`animateOffsetAsState` in the sessions bar, and an `Animatable`-driven enter animation on the float window and bubble. No `TerminalView`, gesture, or `WindowManager` logic changes.

**Tech Stack:** Kotlin + Jetpack Compose (foundation 1.12.1, compose-bom 2026.09.00), all in `:app`.

**Spec:** `docs/specs/2026-11-14-ui-motion-design.md`

## Global Constraints

- All in `:app` Compose (`app/src/main/java/com/termux/app/ui/`). No `:terminal-view`/`:terminal-emulator`/`:termux-shared` change.
- Motion must stay gated on `Theme.kt#shellAnimationsEnabled()` — instant when the system "remove animations" setting is on. Do not regress this.
- No new dependency; use `androidx.compose.animation.*` and `androidx.compose.foundation.lazy` already in the tree.
- No JVM unit tests (declarative Compose; `:app` has no Compose UI test infra). Verification is `:app:assembleDebug` + full `./gradlew test` green + device check D-15.
- Commits: Conventional Commits, capitalized type + present-tense description; every commit GPG-signed (`git commit -S`).

## Review Focus

These have no unit-test seam (declarative Compose); each is pinned by a D-15 device-check item in Task 4 rather than a JVM test.

1. **System animations off** — every transition must be instant; the `shellAnimationsEnabled()` gate must cover all three effects.
2. **Empty sessions list** — no tabs, so `animateItem`, the indicator and `animateColorAsState` must be inert, not crash.
3. **Reorder while dragging** — the dragged tab keeps its own `graphicsLayer.translationX`; the other tabs animate around it with no conflict.
4. **Rapid add/close** — interrupted `animateItem`/`Animatable` animations settle without losing session order (order lives in `SessionsState`).
5. **Float swap** — the enter animation fires on each new window composition and does not desync the drag/resize clamps in `FloatWindowGeometry`.

**Interfaces:**
- Consumes: `shellAnimationsEnabled()` from `com.termux.app.ui.theme`.

- [ ] **Step 1: Add the spring spec and apply it**

In `TerminalShellHost`, define
`val springSpec = spring(dampingRatio = Spring.DampingRatioMediumBouncy, stiffness = Spring.StiffnessMedium)`
(from `androidx.compose.animation.core.Spring`). Replace the two `AnimatedVisibility` blocks (the
sessions bar at lines 199–215 and the extra-keys bar at lines 250–267) so their `enter`/`exit` use
`expandVertically(springSpec) + fadeIn(springSpec)` / `shrinkVertically(springSpec) + fadeOut(springSpec)`
when `animationsEnabled`, still `EnterTransition.None`/`ExitTransition.None` otherwise. Do not touch
the expanded-state `rememberSaveable`, the restore handles or the callbacks.

### Task 2: Animated session tabs

**Files:**
- Modify: `app/src/main/java/com/termux/app/ui/sessions/SessionsBar.kt`

**Interfaces:**
- Consumes: `TabBounds` (existing, from `SessionReorder.kt`) with `index`/`startPx`/`endPx`.
- Produces: no new public API.

- [ ] **Step 1: Add item add/remove/reorder animation**

On the `LazyRow` item composable in `SessionsBar`, add `Modifier.animateItem()` (from
`androidx.compose.foundation.lazy`, `LazyItemScope`), so a tab slides/fades into place on add, remove
and reorder. The dragged tab is excluded: it already drives its own `graphicsLayer.translationX`.

- [ ] **Step 2: Animate the active-tab surface**

In `SessionTab`, replace the instant `containerColor`/`contentColor` selection (lines 265–274) with
`animateColorAsState(...)` (from `androidx.compose.animation`) keyed on `item.active`, so the active
tab's surface and content colour fade in/out.

- [ ] **Step 3: Add the sliding active indicator**

Add a thin rounded pill under the active tab: a `Box` sized to the active tab's width and positioned
via `Modifier.offset { IntOffset(x.roundToInt(), 0) }` driven by `animateIntOffsetAsState(...)` and
`animateDpAsState(...)` keyed to the active tab's measured bounds from the existing `tabBounds` map
(`startPx`/`endPx`). It is a sibling of the `LazyRow`, so its slide does not relayout the tabs. When
there is no active tab it renders nothing.

- [ ] **Step 4: Build and full test**

Run: `./gradlew :app:assembleDebug`

### Task 3: Float enter animation

**Files:**
- Modify: `app/src/main/java/com/termux/app/ui/floating/FloatingWindow.kt`
- Modify: `app/src/main/java/com/termux/app/ui/floating/FloatingBubble.kt`

**Interfaces:**
- Consumes: the spring spec from Task 1 (same values).

- [ ] **Step 1: Add the enter animation to `FloatingWindow`**

Wrap the root `Column` in a `graphicsLayer { scaleX = scale; scaleY = scale; alpha = scale }` where
`scale` is an `Animatable(0f)` animated to `1f` in `LaunchedEffect(Unit)` with
`spring(dampingRatio = Spring.DampingRatioMediumBouncy, stiffness = Spring.StiffnessMedium)`
(~150 ms feel). Do not change the header, the `AndroidView`, the resize handle, or the
`SideEffect` focus handling.

- [ ] **Step 2: Add the matching enter animation to `FloatingBubble`**

Apply the same `Animatable`-driven `graphicsLayer` scale+fade to the bubble's root `Box`. Do not change
the tap/drag gesture reporting.
